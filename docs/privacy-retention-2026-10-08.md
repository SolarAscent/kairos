# Kairos恰时隐私指引填写与保存期限

微信后台「固定存储期限」填写 **365 天**。一年覆盖年度计划、地点心愿及历史记录回看，期满自动清理。账号连续 365 天没有成功登录、刷新或已认证使用时清理账号及其全部数据。已认证使用每分钟最多更新一次活动时间。

## 保存与删除规则

- 原始文字、图片、转写稿、生活事项及目的地：按创建时间保存最多 365 天，修改、重新整理、登录不会延长记录的期限。源记录先到期时，同时删除它产生的事项，即使派生事项较新。
- 建议、追问、反馈、画像信号、模型调用结果、审计与队列：期限不超过 365 天；源记录到期后清理相关副本。为清除可能包含旧来源的会话摘要，同一用户当时已有的建议会话一并清理，用户可重新请求建议。其他用户的记录保持隔离。
- 身份标识：用于持续提供账号服务；账号连续 365 天未使用后清理。账号设置自最近保存起不超过 365 天。
- 精确当前位置快照：到其 purge_at 或创建后两小时即清理，取较早期限；不再依赖用户再次访问才清理。
- 原始音频：开发者后端实时中转，不持久落盘；转写稿随源记录清理。第三方服务的留存依其适用协议，不受本程序数据库任务控制。
- 登录会话、幂等缓存及显式设定较短 retain_until 的资产：优先使用更短期限。
- 小程序本机临时文件：原图查看缓存的文件名没有账号标识，应用启动、切换或退出账号时使在途读取失效并清理，需要时从服务端重新读取。应用启动时还清理上次未完成分享的导出文本和其他账号头像；当前账号正常头像与正在提交的图片保持可用。头像资料读取后只保留服务器当前版本。

## 实现与运行

新增迁移 `packages/db/migrations/0004_privacy_retention.sql`，新增最后使用时间并根据已有会话、记录、建议及用户时间回填，避免部署当天重置所有历史账号的计时。

后台 Worker 启动即执行 `apps/worker/src/retention.ts`；空闲时每分钟检查，有积压时连续执行每批最多 100 条根记录的事务。外键级联与明确删除处理原图、转写、投影、来源、候选、建议、反馈、模型输出、无用户外键的队列和审计、相关幂等缓存。数据被数据库 DELETE 删除，不是仅设置 deleted_at 或隐藏列表。

任务使用事务级 advisory lock 避免多实例重复执行；删除处理中事件的租约，防止模型晚返回重建已删除数据。事务出错全部回滚，记录 `RETENTION_PURGE_FAILED` 并自动重试。日志只输出类型计数或错误码，不输出用户标识、记录、坐标或数据库错误详情。

发布必须先完成数据库迁移，再更新 API 与 Worker。测试只使用随机独立 PostgreSQL schema；本轮不执行线上清理。代码已实现不等于服务器已经启用，后台指引对外生效应与实际部署同步。

仓库目前没有数据库备份计划，也没有外部图片对象存储。若实际服务器另有快照、pg_dump、云备份、旧数据库副本或持久日志，需要在对外承诺生效前核对期限和恢复流程；恢复后必须先迁移并执行清理再开放服务。数据库清理无法删除未纳入配置的外部备份，也不控制第三方供应商的留存。
