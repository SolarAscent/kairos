# 生活卡片的偏好学习

`POST /v1/life/:id/rating` 接收 `LIKE`、`DISLIKE`、`NONE`。它表示目标评价状态；再次点击同一按钮时，客户端发送 `NONE`。写入需 UUID `X-Idempotency-Key`，同一个键重试不会重复学习，同一个键改变请求会返回冲突。明确评价即时写入原有 `preference_signals`，无需等待模型或 Worker。

同一对象的明确评价最优先。类别喜好只做小幅、带样本平滑的泛化，一次赞不会使全部同类对象压过其他对象。接受、执行、完成按一次推荐的行动生命周期合并，只取最强反馈；行为依据保留 365 天、按 90 天半衰期衰减。普通跳过、没时间、太远、低精力不表示不喜欢；明确 `NOT_INTERESTED` 或 `DISLIKE` 的拒绝才参与负向学习。撤回不会保留该对象原来的赞踩票。

`GET /v1/life/stacks` 一次返回各非空类别首批 10 张。`POST /v1/life/deck` 用 `kind`、`cursor`、`limit` 继续读取该类别，覆盖所有 `ACTIVE` 和 `RESOLVED` 对象。返回 `myRating` 和 `preferenceScore`；偏好同分时使用已有对象的重要程度，再按保存时间和 ID 排序。模型已有的重要程度仅作为辅助，并非新的内容理解或跨主题偏好推断。原生活筛选接口继续使用其时间顺序，同时返回当前评价与偏好分数。

偏好分页固定首批的 `asOf`，不可变评价历史使后续赞踩和撤回不会改变这次翻页的顺序。新收纳对象不插入旧分页；新请求读取最新评价。删除后不再返回该卡片，但它在旧分页时刻的类别贡献保留到该次分页结束，避免页间重复。游标限定类别和排序版本，有效期 24 小时。

`DELETE /v1/life/:id` 使用幂等键软删除对象，取消该对象正在进行的计划、关闭实际推荐了它的会话，并屏蔽相关候选；仅在候选池中含有该对象、实际推荐别的对象的会话保持原状态。删除不等同于不喜欢，也不会产生类别负向信号。原输入、对象事实和审计来源继续保留。

生活分类排序和 Now 共用 `PreferenceReader`，Now 仍保留时间、预算、地点与执行条件检查；偏好不绕过这些条件。本次没有新增推理调用，也没有从未结构化的“我喜欢……”描述猜测跨主题偏好。

Now 保留原 200 个近期／紧迫候选，并额外合并最近明确点赞的最多 50 个当前活动对象，去重后最多 250 个；较早的心愿也可以被重新召回。排除条件、删除状态和所有者隔离同样适用于额外召回。原会话不因为后续点赞而跳换正在展示的建议；删除后读取或幂等重放旧会话会核对实时状态并清除已删除的推荐。
