# 腾讯地图接入与验收（2026-10-05）

## 控制台与服务端

腾讯位置服务应用为“KAIROS生活决策”（生活服务），Key 名称为“KAIROS服务端”。用户亲自接受协议并创建 Key；本项目采用 WebService API，由 API 和 Worker 调用腾讯 HTTPS 服务，小程序不携带地图 Key。微信小程序 SDK 产品勾选并非本架构要求。

Key 使用授权 IP `47.82.69.31`，未留空或授权地址段。Key 以 RSA OAEP 加密传输到测试服务器，并存入权限为 600 的服务端环境文件。没有在源码、小程序、请求回包或本说明中记录密钥值。测试发布保留现有数据库、域名与端口。

账户现有免费额度需要分配到 Key：地址解析及步行路线分别分配 6000 次/日、5 次/秒。这里的数字是控制台当日配置，未来额度可能变化；没有购买额外配额。省、市等粗地点不转换为伪精确坐标。

环境变量：

```dotenv
TENCENT_LBS_KEY=<服务器专用 WebService Key>
TENCENT_LBS_SECRET=
```

当前采用 IP 校验，因此无需签名 Secret。若以后切换 SN，必须同时配置服务器 Secret 并重启 API、Worker。服务器出口 IP 变化需同步控制台白名单。

## 本产品接入的链路

- 地址解析：明确目的地 → 后台 Outbox → 腾讯地理编码 → 独立外部来源事实与生活投影 → 生活列表位置筛选。
- 路线核验：用户主动提供本次精确位置 → 有效起点与目的地 → 分别查询去程、返程步行路线 → 行动总耗时。
- 新 Capture 自动回填与旧地点列表补全单次均最多五个；已核实地址复用，模糊地址保持未知。新录入通道不被后台补全占满。
- 手机当前位置只用于用户主动操作，无持续后台定位或精确 GPS 长期缓存。已有目的地坐标与当前物理位置保持区分。

接口：`GET /v1/locations/status`，`POST /v1/locations/refresh`（objectIds 最多五个、不含 GPS），`POST /v1/locations/:id/refresh`。登录、所有者隔离、幂等键及对象版本校验均保留。状态 configured 表示服务配置存在，实际能力以腾讯返回结果为准。

本次产品范围为地址解析、地点持久化及步行往返路线；驾车、公交、预约、商家营业时间等尚未接入，不能用模型估计冒充核验。

测试服务器当前发布为 `maps-20261005-2236`，前一版为 `planning-20261005-2150`；数据库容器保持不变。22:47，公开 HTTPS API 的真实验收通过：授权测试用户将具体目的地入队，Worker 完成腾讯地址解析并保存 `EXTERNAL_VERIFIED` 来源坐标，生活查询返回 `hasLocation=true`；省级“新疆”保持无精确坐标，地图 Provider 拒绝把它当作明确目的地。去程、返程独立核验均为 605 米、540 秒。服务器回执为 `/opt/kairos-staging/logs/maps-public-maps-20261005.json`。

同一发布的真实 Qwen 输入“我现在在广东，只有20分钟，想去新疆旅行，旅行预算3000元。”也验收通过：广东作为当前区域，20 分钟作为有截止时间的可用窗口，3000 元保留为旅行预算；生成 5 分钟旅行准备行动，没有生成立即去新疆的路线。接受、恢复、完成行动后，旅行目标仍保持 ACTIVE。受理耗时 198 毫秒，理解完成耗时 4618 毫秒，这是本次样例，不是速度保证。回执为 `/opt/kairos-staging/logs/maps-public-planning-20261005.json`。

统一构建通过，本地全部 285 项测试通过；地图模块专项 13 项覆盖自动 Capture 入队、坐标来源、附近查询、地址修改、对象版本与租约并发、同地址缓存以及模糊地点拒绝。真实传输按每进程、每 Key、每路径约 4 QPS 排队；多副本部署需共享限流或重新调整额度，不能声称是全集群限流。

测试使用独立本地数据库随机 schema，真实公开 API 探针只创建可识别的临时测试用户，并清理其对象与任务。微信预览已成功上传，并修正定位用途说明超过微信 30 字限制的问题。真实手机定位仍需要用户在手机上允许定位，并通过新版预览验证；后台隐私声明及定位权限是否适用于正式上线仍需按微信控制台的实际要求验收。
