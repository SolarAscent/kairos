# 个人资料与微信账号关联

入口为首页右上角的头像／“我的”，进入 `pages/profile/index`。页面延续已有的雾绿底色、深绿文字、宋体标题和圆角表单，顶部以 K 字母头像作为尚未设置资料的默认状态。头像、昵称和个人简介统一通过“保存修改”提交，未设置资料仍可使用原有功能。

## 可用功能

- 微信原生 `button open-type="chooseAvatar"` 选择头像，`input type="nickname"` 填写昵称；昵称也支持自行输入。
- 昵称 1–32 个字符，个人简介选填，最多 160 个字符。
- 头像在客户端压缩至最长边 512 px；服务器只接受不超过 256 KB 的 JPEG／PNG 图片内容，验证格式标记、实际字节长度与 Base64 编码。不会接收临时文件路径、远程头像 URL 或客户端传来的用户身份。
- 支持恢复默认头像；省略头像字段表示保留，传 `null` 表示移除。取消选择不改动已存资料。
- 保存成功后同步首页的昵称和头像；失败保留表单，原样重试沿用操作键，修改内容后生成新的操作键。
- 显示真实微信关联／开发体验账号状态、内部账户 ID、加入日期。提供复制账户 ID 和退出登录。
- 自定义返回按钮在有未保存修改时提示；微信头像选择器引起的隐藏／显示不重置表单。

## 账号与数据关系

现有服务端流程为 `wx.login` 临时代码 → `code2Session` 验证 → `user_identities(WECHAT, OpenID)` → 内部 `users.id`。资料、Capture 和 Life 使用同一内部用户 ID，同一微信账号重复登录或换设备登录可找回同一账户。昵称／头像不是账户身份，修改它们不会新建用户或改变记录归属。AppSecret 与微信 `session_key` 不进入客户端。

真实微信登录后可补记服务器取得的 UnionID；当前部署继续绑定一个 AppID，不根据 UnionID 自动合并账户。不支持跨 AppID 复用身份库或把开发体验账号自动迁移到真实微信。需要跨应用关联时，必须另行设计经验证的身份绑定与冲突处理。

登录与头像、昵称填写是独立操作。资料只在本人页面展示；微信授权填写由用户主动触发，页面不会索取手机号、通讯录等无关信息。

## 接口与存储

| 接口                        | 用途                                                            |
| --------------------------- | --------------------------------------------------------------- |
| `GET /v1/users/me`          | 资料元数据和身份关联状态，不含图片内容、OpenID、UnionID         |
| `GET /v1/users/me/avatar`   | 经鉴权读取本人头像及版本，JSON 图片内容写入微信本地文件后显示   |
| `POST /v1/users/me/profile` | 幂等保存昵称、简介和可选头像；必须提供 UUID `X-Idempotency-Key` |

新增迁移 `packages/db/migrations/0003_user_profile.sql`，在已有用户表中添加资料与头像字段，并约束头像数据的一致性与长度。保留已有账户，默认昵称为空、简介为空、头像为空。头像与元数据同事务提交，幂等记录只保存返回的元数据，不重复存储头像。

目前头像采用有容量限制的 PostgreSQL 存储，适合现有独立账户规模，也避免新增对象存储配置。头像通过本人鉴权接口取得，不创建公开图片链接。客户端缓存按用户和头像版本区分，退出／切换用户清除当前缓存，过期会话或迟到响应不会恢复旧账号的页面内容。以后用户量增长时可把图片迁移到私有对象存储，保留当前用户归属与接口语义。

## 验证与接入

自动验证包括编译后的小程序页面（禁用 `eval`／Zod JIT）、表单失败重试、默认头像、关联状态、退出后的数据清理，以及隔离 PostgreSQL schema 下的 HTTP／迁移验证。身份 Provider 的验证响应在自动测试中模拟，不能视为真实微信平台登录验收。

部署顺序：先在目标数据库运行 `pnpm db:migrate`，再更新 API，最后使用真实微信登录配置运行 `pnpm build:miniprogram`。旧 API 尚未提供本轮接口，单独替换客户端不能完成资料保存。真实环境需复核微信后台头像／昵称的隐私说明和授权展示，再验证手机选择头像、昵称自动填写、保存后重新进入、退出重登和另一个微信账号的隔离。

本地独立体验工程使用 `develop + mock` 和隔离测试 schema；不会代表真实微信授权或线上部署完成。自动测试、原生模拟器交互和真实手机验收分别记录。
